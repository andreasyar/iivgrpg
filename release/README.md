# IIVGRPG 2.3.0

Дистрибутив с готовым JAR и статическим клиентом для Docker Engine
с плагином Docker Compose v2+.
На Windows/macOS нужен Docker Desktop в режиме Linux-контейнеров.
Docker-образы создаются на компьютере пользователя: Dockerfile только копируют
готовые файлы проекта в стандартные образы JRE 21 и Nginx. Компиляции нет.
JDK, Maven и Node.js не требуются. При первой сборке нужен интернет для загрузки
базовых образов и MariaDB. Архив с JAR и JavaScript общий для amd64 и arm64;
Docker выбирает базовые образы под архитектуру компьютера.

## Запуск

Распаковать архив, перейти в полученный каталог и выполнить:

```sh
docker compose up -d --build
docker compose logs -f
```

Открыть <http://localhost:8081>. Адрес WebSocket определяется автоматически.
Для входа можно указать любые логин и пароль из латинских букв/цифр
(например `test` / `test`). Для двух игроков открыть две вкладки и использовать
разные логины.

**Спрайты не входят в дистрибутив.** Без собственного набора PNG графика будет
неполной. Поместить свои ресурсы в каталог `sprites/` рядом с `compose.yaml`:
они доступны клиенту без пересборки и перезапуска контейнеров (обновить страницу).
Ожидаемые имена перечислены в `SPRITES.txt`. Исторические изображения проект не
распространяет, поскольку не обладает авторскими правами на них.

Порт по умолчанию доступен только на локальном компьютере и выбран так, чтобы
не пересекаться с релизом MiniMMORTS (`8080`). Чтобы выбрать другой, создать
рядом файл `.env` со строкой `HTTP_PORT=8082` и повторить `compose up -d`.
Для доступа из локальной сети добавить `BIND_ADDRESS=0.0.0.0`; другие игроки
открывают `http://<адрес компьютера>:8081`. Это не готовый публичный
интернет-сервис: сервер использует устаревший Netty 3, HTTPS нет, пароли БД
демонстрационные.

## Настройка и остановка

Игровая конфигурация находится в `config/server.xml`. После изменения выполнить
`docker compose restart server`. Порт сервера внутри конфигурации оставить 8015:
на него настроен прокси. Параметры MySQL/MariaDB должны совпадать с сервисом
`db` в Compose: сервер подключается к БД при старте, хотя текущий MMORTS-режим
хранит игру в памяти и не использует таблицы старого MMORPG.

```sh
docker compose ps
docker compose logs --tail=100
docker compose down
```

Игра хранится в памяти: перезапуск сервера сбрасывает мир и отключает игроков.
Файловые логи и данные MariaDB сохраняются в Docker volumes;
`docker compose down -v` удаляет их.

## Проверка и обновление

В Linux можно проверить содержимое архива командой `sha256sum -c SHA256SUMS`.
Для обновления остановить старый стенд, распаковать новый выпуск в отдельный
каталог, перенести собственные `sprites/`, `.env` и нужные настройки сервера,
запустить новый стенд командой `docker compose up -d --build`.
Для возврата к предыдущей версии остановить новый и запустить старый каталог.
Не запускать два выпуска одновременно с одинаковым Compose project name.
