# IIVGRPG 1.5.0

Дистрибутив MMORPG версии 1 с готовым JAR, статическим клиентом и спрайтами
для Docker Engine с плагином Docker Compose v2+.
На Windows/macOS нужен Docker Desktop в режиме Linux-контейнеров.
Docker-образы создаются на компьютере пользователя: Dockerfile только копируют
готовые файлы проекта в стандартные образы JRE 21 и Nginx. Компиляции нет.
JDK, Maven и Node.js не требуются. При первой сборке нужен интернет для загрузки
базовых образов и MariaDB. Архив с JAR, JavaScript и PNG общий для amd64 и arm64;
Docker выбирает базовые образы под архитектуру компьютера.

## Запуск

Распаковать архив, перейти в полученный каталог и выполнить:

```sh
docker compose up -d --build
docker compose logs -f
```

Открыть <http://localhost:8082>. Адрес WebSocket определяется автоматически.
Старый сервер регистрирует неизвестный логин автоматически; для входа можно
указать `test` / `test`. Для двух игроков открыть две вкладки и использовать
разные имена (3–16 латинских букв, цифр или `_`) и пароль от 4 символов.

Спрайты тестового мира входят в дистрибутив. Кэш карт сервер создаёт при старте
из воспроизводимой схемы БД; пока файлы кэша не готовы, обновить страницу позже.
Список включённых PNG — в `SPRITES.txt`.

Порт по умолчанию доступен только на локальном компьютере и выбран так, чтобы
не пересекаться с релизом IIVGRPG 2.x (`8081`) и MiniMMORTS (`8080`). Чтобы
выбрать другой, создать рядом файл `.env` со строкой `HTTP_PORT=8083` и
повторить `compose up -d`. Для доступа из локальной сети добавить
`BIND_ADDRESS=0.0.0.0`; другие игроки открывают `http://<адрес компьютера>:8082`.
Это не готовый публичный интернет-сервис: сервер использует устаревший Netty 3,
HTTPS нет, пароли БД демонстрационные.

## Настройка и остановка

Игровая конфигурация находится в `config/server.xml`. После изменения выполнить
`docker compose restart server`. Порт сервера внутри конфигурации оставить 8015:
на него настроен прокси. Параметры MySQL/MariaDB должны совпадать с сервисом
`db` в Compose. Путь кэша карт — `/run/iivgrpg/cache`; тот же том смонтирован
в веб-контейнер как `/usr/share/nginx/html/cache`.

```sh
docker compose ps
docker compose logs --tail=100
docker compose down
```

Аккаунты и персонажи сохраняются в MariaDB. Исторический код не сохраняет
текущую позицию при выходе. Перезапуск сервера разрывает соединения — обновить
клиент. Данные MariaDB и кэш карт хранятся в Docker volumes;
`docker compose down -v` удаляет их, включая тестовый мир.

## Проверка и обновление

В Linux можно проверить содержимое архива командой `sha256sum -c SHA256SUMS`.
Для обновления остановить старый стенд, распаковать новый выпуск в отдельный
каталог, перенести `.env` и нужные настройки сервера, запустить новый стенд
командой `docker compose up -d --build`. Для возврата к предыдущей версии
остановить новый и запустить старый каталог. Не запускать два выпуска
одновременно с одинаковым Compose project name.
