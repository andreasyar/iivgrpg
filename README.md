# IIVGRPG — версия 1 (MMORPG)

Ветка `codex/version-1` создана от `8ea5a33`, текущего коммита после переноса
истории и контейнеризации. Здесь запускаются старый HTML5-клиент
`client/test_001.html` и сервер `mmo.MmoServer`. Клиент и сервер MMORTS
из ветки `main` в этой ветке не используются и удалены.

Это восстановление запуска существующей MMORPG, а не добавление башен, волн,
монстров или предметов. Работают персонажи, карта с объектами, обход препятствий,
сетевое движение и чат. Тестовый мир создан заново: это не архивная карта.

## Запуск

На хосте нужны Docker Engine и Docker Compose. Java 21, Maven, Node.js и MariaDB
работают в контейнерах с UID/GID пользователя хоста. Перед первым запуском,
после удаления volumes или смены UID/GID выполнить настройку от обычного
пользователя хоста (без `sudo`):

```sh
sh dev/setup.sh
docker compose up -d
docker compose logs -f server
```

Дождаться `Web server bind on port 8015`, открыть
[клиент](http://localhost:5174/) и нажать Login. Поля заполнены `test` / `test`.
Старый сервер регистрирует неизвестный логин автоматически; для второго окна
использовать другое имя (3–16 латинских букв, цифр или `_`) и пароль от 4 символов.
Повторный вход требует того же пароля. Сервер автоматически подставляется как
`ws://localhost:5174/ws/`; Vite проксирует соединение в Java.

Управление: ЛКМ по свободной клетке — движение, поле чата и Send — сообщение,
клавиша `a` — проходимость. Вблизи старта расположены деревья, цветы и пирамида.
Вторая карта загружается для совместимости клиента; переход между картами не
добавлен. Камера исторически центрируется на персонаже даже у края мира.

HTTP опубликован на `127.0.0.1:5174`, прямой WebSocket — на `127.0.0.1:8016`.
Другие порты задаются через `CLIENT_PORT` и `SERVER_PORT`:

```sh
CLIENT_PORT=5175 SERVER_PORT=8017 docker compose up -d
```

## Как устроен стенд

- `client`: Vite раздаёт корень `client/`, главная страница — `test_001.html`.
  Изменения скриптов перезагружают страницу. Игровой `Map` переименован в
  `GameMap`, чтобы сохранить встроенный JavaScript Map для Vite.
- `server`: автоматически пересобирает Java при изменениях исходников,
  `server/pom.xml` и `dev/server/config.xml`. При ошибке сборки предыдущая JVM
  продолжает работать. Входной класс JAR — `mmo.MmoServer`; конфигурация передаётся
  аргументом. Без аргумента читается `server.xml` из текущего каталога.
- `db`: MariaDB и отдельный том `database_v1`. При первом запуске пустого тома
  выполняет `dev/db/001-world.sql`: создаёт схему и две тестовые карты с объектами.
  Архивные аккаунты и дампы не импортируются. Изменение SQL не переинициализирует
  существующий том; дальнейшие изменения БД нужно применять отдельно.
- `world_cache`: сервер формирует `groundtiles.js`, `objects.js`, `map_1.js` и
  `map_2.js` из БД; клиент читает их через `/cache/`. Пока карты не загружены,
  кнопка Login отключена. Если сервер ещё не готов, обновить страницу позже.

`dev/setup.sh` записывает текущие `LOCAL_UID` и `LOCAL_GID` в локальный `.env`,
сохраняя остальные настройки. Compose использует эти значения и при сборке,
и при запуске всех трёх сервисов. Скрипт создаёт точки монтирования на хосте до
Docker, собирает образы, останавливает сервисы и исправляет владельцев существующих
каталогов и томов, включая `world_cache` и `database_v1`. Только эта подготовка
выполняет разовые команды от root; Node.js, Maven, Java, Python и MariaDB
работают от пользователя хоста. Для самостоятельных команд Compose без `.env`
используются UID/GID `1000:1000`.

Домашний каталог клиента и сервера — `/home/developer`; npm-кэш находится в
`/home/developer/.npm`, Maven — в `/home/developer/.m2`. Каталог сокета MariaDB
создаётся через tmpfs с теми же UID/GID. Запуск контейнеров не меняет владельца
исходников.

При переходе с `main` выполнить `sh dev/setup.sh`, затем `docker compose up -d`:
Compose заменит контейнер БД, подключив `database_v1`. Старый том
`iivgrpg_database` сохраняется; при возврате на `main` тот же запуск подключит
его обратно. Кэши зависимостей общие. Одновременный запуск обеих веток требует
отдельных Compose project names и разных портов.

Перезапуск Java разрывает соединения — обновить клиент. Аккаунты и персонажи
сохраняются в БД, но исторический код не сохраняет текущую позицию при выходе.
При завершении JVM без изменений файлов использовать `docker compose restart server`.
После изменения Dockerfile повторить `sh dev/setup.sh`, затем `docker compose up -d`.
`docker compose down -v` удаляет тома стенда; перед следующим запуском снова
выполнить `sh dev/setup.sh`.

## Проверки и сборка

После готовности сервера:

```sh
# HTTP, две карты, вход персонажей, взаимная видимость, чат, обход деревьев и выход
docker compose exec -T client node /workspace/dev/smoke.mjs

# Проверка синтаксиса и сборка старого клиента с кэшем мира и локальной графикой
docker compose exec client npm run build

# JAR со всеми зависимостями
docker compose exec server mvn -B -ntp clean verify
```

Не запускать ручную Maven-сборку одновременно с автоматической. Ручная сборка
не заменяет работающую JVM. Результаты хранятся в volumes; экспорт:

```sh
docker compose cp server:/build/server/target/iivgrpg-server.jar /tmp/iivgrpg-server.jar
docker compose cp client:/workspace/client/dist /tmp/iivgrpg-client
```

Для статического клиента нужен WebSocket-прокси `/ws/` к Java-серверу и актуальный
кэш того же мира. Сборка требует запущенного сервера, который уже создал кэш.

```sh
docker compose down
```

Останавливает стенд с сохранением данных. `docker compose down -v` удаляет тома
текущего стенда, включая тестовую БД и кэш мира. Перед следующим запуском снова
выполнить `sh dev/setup.sh`.

## Ресурсы и история

Спрайты тестового мира версии 1 лежат в `client/` и входят в репозиторий:
`grass.png`, `grass2.png`, `player.png`, `path.png`, `path_end.png`, `tree.png`,
`flower.png`, `pyramid1.png`–`pyramid4.png`.

Проект содержит последовательность 129 ревизий Google Code SVN за 2011–2012 годы
и последующие изменения инфраструктуры. Исходное имя — `iivgprg`.
`trunk/` развёрнут в корень, `wiki/` сохранён рядом с кодом. Архивные спрайты
и дампы исключены из всей истории. Версии в CHANGELOG присвоены ретроспективно.
Дополнения локальных архивов сохранены в независимых ветках `historical/*`.

Зависимости исторического Java-сервера: Netty 3.4.4.Final, Gson 1.7.1,
MySQL Connector/J 5.1.17; Maven загружает их из Central по `server/pom.xml`.
Это локальный dev-стенд с открытыми dev-паролями.
Подробности переноса: [migration/README.md](migration/README.md),
[учёт ревизий и локальных копий](migration/import-report.json).
